# Wallhaven 검색 개선

개발 브랜치: `feat/wallhaven-browser` (preview.4 소스 기준).

## 사용법

- 검색어를 입력하고 Enter 또는 **검색**을 누르면 1페이지부터 검색합니다.
- **정렬** 버튼으로 자동 / 관련도 / 인기 / 최신 / 조회수 / 저장 수 / 무작위를 순환합니다.
- 인기 정렬의 기간, 일반·애니·인물 카테고리, 최소 해상도(FHD/QHD/UHD)를 선택할 수 있습니다. 카테고리는 최소 하나를 유지합니다.
- `+landscape -people`, `id:123`, `@username` 등 Wallhaven 검색 문법을 그대로 전달합니다.
- **☆ 검색 저장**은 현재 입력한 태그·검색식과 필터를 함께 저장합니다. 동일한 검색식·필터에서 다시 누르면 삭제합니다.
- 즐겨찾기를 누르면 저장한 필터까지 복원해 1페이지를 검색합니다. 한 줄에 4개씩 보이며 오른쪽 버튼으로 다른 즐겨찾기를 볼 수 있습니다.
- API 페이지는 하단 화살표 또는 번호 입력 후 Enter / **이동**으로 전환합니다.
- 한 API 페이지의 최대 24개 결과는 6장씩 표시됩니다. 휠, PageUp/PageDown, **이전 6장 / 다음 6장**으로 전부 볼 수 있습니다. 입력창 밖에서는 방향키로 사진을 선택하고 Ctrl+좌우로 API 페이지를 이동합니다.
- 입력 중인 검색어는 아직 검색된 조건과 분리됩니다. 검색어만 고치고 페이지를 넘기면 마지막으로 검색한 조건을 유지합니다.
- **새로고침**은 현재 페이지의 검색 캐시를 무시합니다. 검색어가 변경됐다면 새 검색을 수행합니다.
- 사진 클릭은 선택입니다. **사진 받기**로 다운로드한 뒤 로컬 선택창에서 Enter로 배경화면·테마를 적용합니다.

즐겨찾기는 Wallhaven 계정이 아닌 이 PC에 저장됩니다. 사이트 태그 목록을 자동 수집하는 기능은 포함하지 않으며, 태그명·정확한 태그 ID·복합 검색식을 즐겨찾기로 저장합니다.

## 저장 및 캐시

- 설정: GlazeBar 실행 폴더의 `theme-state/wallhaven.json`. 마지막 검색·필터·검색어 즐겨찾기·하트 사진을 원자적으로 저장합니다.
- 검색 결과: `%LOCALAPPDATA%\GlazeBar\wallhaven-search-cache`, 유효 기간 7일. 검색식, 모든 필터, 페이지, 무작위 시드를 캐시 키에 포함합니다.
- 웹 썸네일: `%LOCALAPPDATA%\GlazeBar\wallhaven-thumbnail-cache`, 긴 변 최대 480px JPEG(품질 82). Wallhaven의 작은 썸네일을 사용하며 원본 사진을 미리 다운로드하지 않습니다. 썸네일 URL별 캐시를 재사용합니다.
- **캐시 보관함**은 이미 내려받은 사진 미리보기를 인터넷 요청 없이 모아 보여줍니다. **♥ 보관함**은 하트를 누른 사진만 보여줍니다.
- **♡ 사진 보관**은 저해상도 미리보기를 디스크에 저장한 뒤 하트를 등록합니다. 원본 사진은 자동 다운로드하지 않습니다. 하트를 해제해도 일반 미리보기 캐시는 지우지 않습니다.
- 미리보기에는 자동 만료나 용량 제한을 두지 않습니다. 검색 캐시의 7일은 서버의 검색 목록 갱신 주기이며, 보관된 사진 미리보기의 유효 기간이 아닙니다.
- 보관함 옆에 두 웹 캐시 폴더의 합산 MB와 JPEG 사진 개수를 표시합니다. 원본 다운로드 폴더의 용량은 포함하지 않습니다.
- 웹 검색 중 캐시 파일이 손상되면 다시 받아 복구합니다. 캐시 쓰기가 실패해도 검색과 미리보기는 동작합니다.
- 검색/API 작업과 썸네일 작업을 별도 스레드로 실행합니다. 이전 요청을 취소하고 응답 revision을 확인해 오래된 결과가 새 검색을 덮지 않게 합니다.
- 검색과 다운로드는 기존과 같이 SFW만 지원합니다. API 키나 계정 연결은 추가하지 않았습니다.

공식 [Wallhaven API 설명](https://wallhaven.cc/help/api)에 따라 무작위 시드를 전달합니다. 실 서버 검증에서는 지정한 시드와 다른 응답 시드를 반환하는 경우가 있어, 무작위 정렬의 페이지 간 중복 제거를 보장하지 않습니다.

## 검증

Windows SDK의 `rc.exe`가 PATH에 있어야 합니다.

```powershell
cd native-rust
cargo test --locked
cargo test --locked wallhaven::tests::live_search_filters_and_pagination -- --ignored --nocapture
cargo build --locked --release
```

자동 검증에는 검색 인코딩·필터 검증·빈 페이지 처리·페이지 번호 범위·6장 묶음 경계·즐겨찾기 저장/삭제/복원·캐시 재사용·만료·강제 갱신·손상 복구·취소를 포함합니다. 캐시 테스트는 임시 폴더와 가짜 전송기를 사용하며, 캐시를 읽을 때 네트워크 전송기를 호출하지 않는지 확인합니다.

기존 `--validate-native`는 검색 클릭, 휠, 페이지 번호 입력과 이동 이벤트도 검사합니다. 실제 Windows 창에서도 검색어 즐겨찾기, 번호 입력 후 Enter 페이지 이동, 하트 보관, 오프라인 보관함, 캐시 용량 표시를 검증했습니다. 테스트 환경에서 검색 결과를 처음 받을 때 약 1.14초, 같은 결과의 캐시 재사용은 약 46ms였습니다. 네트워크·PC 상태에 따라 달라집니다.

`--render-wallhaven`은 테스트 이미지로 다크/라이트, 100%/175% UI 검토 이미지를 `ui-reference/rust`에 생성합니다. 실행 파일은 `config.yaml`과 `icons/`가 있는 앱 폴더에서 실행해야 합니다.
